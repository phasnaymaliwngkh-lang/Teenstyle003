Endpoint ทั้งหมดของ TEENSTYLE AI ที่เปิดใช้จริง **119 เส้นทาง** (นับรวม `GET /health` และ `GET /api`)

> **เอกสารนี้ถูกบังคับให้ตรงกับโค้ด**
> [backend/tests/api-contract.test.ts](../backend/tests/api-contract.test.ts) อ่านแผนผัง endpoint
> จาก Express router จริงด้วย [`buildApiMap()`](../backend/src/models/api-map.ts) แล้วเทียบกับตารางในไฟล์นี้
> ทีละแถว — **เพิ่ม endpoint แล้วไม่เขียนลงที่นี่ เทสต์ล้ม · เขียน endpoint ที่ไม่มีจริง เทสต์ล้ม ·
> เขียนสิทธิ์ผิด เทสต์ล้ม** เอกสาร API ที่เพี้ยนจากโค้ดอันตรายกว่าไม่มีเอกสารเลย
> เพราะคนอ่านจะเชื่อว่า "เส้นทางนี้ไม่ต้องมีสิทธิ์"

## ข้อตกลงร่วมของทุก endpoint

### Base URL

| สภาพแวดล้อม         | ค่า                                                              |
| ------------------- | ---------------------------------------------------------------- |
| dev บนเครื่องนี้    | `http://localhost:4000`                                          |
| จากเบราว์เซอร์      | `NEXT_PUBLIC_API_URL`                                            |
| จาก Server ของ Next | `API_INTERNAL_URL` (ถ้าตั้งไว้) ไม่งั้นใช้ `NEXT_PUBLIC_API_URL` |

ยังไม่มีเวอร์ชันใน path (ไม่มี `/v1`) — `GET /api` คืน `version` ของ API มาให้แทน
ถ้าวันหนึ่งต้องแตกเวอร์ชัน ให้เพิ่ม prefix ใหม่ **ห้ามเปลี่ยนความหมายของเส้นทางเดิม**

### รูปแบบ response (ห้ามเปลี่ยน)

```jsonc
// สำเร็จ
{ "success": true, "message": "สำเร็จ", "data": { } }

// ไม่สำเร็จ
{ "success": false, "message": "ไม่พบข้อมูลที่ต้องการ", "errorCode": "NOT_FOUND", "details": [] }
```

ทุก response ผ่าน `sendSuccess()` / `errorHandler` ที่เดียว — **controller ห้าม `res.status().json()` เองเพื่อส่ง error**

### HTTP status และ `errorCode`

| Status | `errorCode`              | เกิดเมื่อ                                                                                  |
| -----: | ------------------------ | ------------------------------------------------------------------------------------------ |
|    400 | `BAD_REQUEST`            | คำขอผิดความหมาย เช่น นับสต็อกได้เท่าเดิม · JSON พัง · แก้บัญชีตัวเอง · path เข้ารหัสไม่ถูก |
|    401 | `UNAUTHORIZED`           | ไม่มี session หรือ session หมดอายุ                                                         |
|    403 | `FORBIDDEN`              | บทบาท/สิทธิ์ไม่พอ · Origin ไม่ใช่ของเรา                                                    |
|    404 | `NOT_FOUND`              | ไม่มีข้อมูล **หรือมีแต่ไม่ใช่ของผู้เรียก** (ดูหัวข้อถัดไป)                                 |
|    409 | `CONFLICT`               | ชนกับสถานะปัจจุบัน เช่น สต็อกไม่พอ · บาร์โค้ดซ้ำ · ลบสินค้าที่มีของถูกจอง                  |
|    413 | `PAYLOAD_TOO_LARGE`      | body เกิน 1MB หรือไฟล์อัปโหลดเกิน 5MB                                                      |
|    415 | `UNSUPPORTED_MEDIA_TYPE` | charset หรือ content encoding ของ body อ่านไม่ได้ (ต้องเป็น UTF-8)                         |
|    422 | `VALIDATION_ERROR`       | Zod ไม่ผ่าน — `details` บอกเป็นราย field (`{ field, message }`)                            |
|    429 | `TOO_MANY_REQUESTS`      | เกิน rate limit                                                                            |
|    500 | `INTERNAL_ERROR`         | ข้อผิดพลาดที่ไม่คาดไว้ — production ตัด `details` ออกเสมอ                                  |
|    503 | `SERVICE_UNAVAILABLE`    | ต่อฐานข้อมูลไม่ได้ หรือบริการภายนอกที่จำเป็นใช้ไม่ได้ — **ลองใหม่ได้**                     |

**ของคนอื่นคืน 404 ไม่ใช่ 403** ทุกที่ (ตะกร้า · คำสั่งซื้อ · ที่อยู่ · รีวิว · บทสนทนา AI)
403 เท่ากับบอกใบ้ว่า id นั้นมีอยู่จริง ซึ่งทำให้เดา id ของคนอื่นได้

### การยืนยันตัวตน

session เก็บใน **ฐานข้อมูล** (ตาราง `Session` ของ Auth.js v5) ไม่ใช่ JWT → เพิกถอนได้ทันที
backend อ่าน token ได้ 2 ทาง:

1. cookie `authjs.session-token` (production: `__Secure-authjs.session-token`) — ใช้ได้ตอน dev
2. `Authorization: Bearer <token>` — ใช้ตอน production ที่ frontend/backend อยู่ต่างโดเมน
   ฝั่ง Server ของ Next อ่าน cookie แล้วส่งต่อให้เองผ่าน `apiFetchAsUser()`

**บทบาทและสิทธิ์อ่านจากฐานข้อมูลใหม่ทุกคำขอ** (`Role ↔ Permission`) ไม่ได้ฝังไว้ใน token
→ เปลี่ยนบทบาทแล้วมีผลทันทีโดยไม่ต้องให้ผู้ใช้ล็อกอินใหม่

### CSRF

ทุกคำขอที่ **เปลี่ยนข้อมูล** ต้องผ่าน `verifyOrigin` ซึ่งเทียบ `Origin` (หรือ `Referer`) กับ `CORS_ORIGIN`
จำเป็นเพราะ production ใช้ cookie `SameSite=None` ซึ่งไม่กัน cross-site POST ให้

มีเส้นทางที่เปลี่ยนเมธอดเป็น POST แต่ **ไม่ผ่าน** `verifyOrigin` อยู่ 3 เส้นทาง ซึ่งเป็นข้อยกเว้นที่ตั้งใจ
(เทสต์ระบุรายการนี้ไว้ตรง ๆ — เพิ่มเส้นทางใหม่เข้ารายการนี้ไม่ได้โดยไม่มีใครเห็น):

| เส้นทาง                              | เหตุผล                                                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| `POST /api/products/availability`    | เป็นการ **อ่าน** — ตรวจสต็อกก่อนกดซื้อ ไม่เขียนอะไรเลย (เป็น POST เพราะส่งรายการ variant มาเป็น body) |
| `POST /api/looks/:slug/availability` | เหมือนกัน — ตรวจว่าซื้อครบชุดได้ไหม                                                                   |
| `POST /api/payments/webhook/stripe`  | Stripe ไม่ใช่เบราว์เซอร์ จึงไม่มี `Origin` — ด่านคือ **ลายเซ็น HMAC** ของ raw body                    |

### Rate limit

| ชั้น          | โควตา                                                                         | ใช้ที่ไหน                                                                      |
| ------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| ทั้ง API      | `RATE_LIMIT_MAX` ต่อ `RATE_LIMIT_WINDOW_MS` (ค่าเริ่มต้น 300 ครั้ง / 15 นาที) | ทุกเส้นทาง                                                                     |
| เข้มเป็นพิเศษ | 20 ครั้ง / นาที                                                               | เส้นทางที่เรียก OpenAI หรือเพิ่มตัวนับ — ดูคอลัมน์ "ต้องมี" ที่เขียน `20/นาที` |

นับต่อ IP และเก็บ state **ในหน่วยความจำ** → ยังใช้ร่วมกันหลาย instance ไม่ได้ (Redis เป็นงานของ STEP 34)
· `req.ip` เชื่อถือได้เท่าที่ `TRUST_PROXY_HOPS` ตรงกับจำนวน proxy จริง (ดู [08-security.md](08-security.md))

⚠️ **เส้นทางที่ถูกจำกัดแบบเข้มต้องถูกเรียกจากเบราว์เซอร์เท่านั้น** ห้ามเรียกจาก Server Component
เพราะคำขอทั้งเว็บจะมาจาก IP เดียวแล้วผู้ใช้ทุกคนแชร์โควตา 20 ครั้ง/นาทีร่วมกัน

### การแบ่งหน้า

รายการที่แบ่งหน้าใช้รูปแบบเดียวกันทั้งหมด:

```jsonc
{ "items": [], "total": 0, "page": 1, "limit": 20, "totalPages": 1 }
```

บางเส้นทางเพิ่มฟิลด์สรุปที่ **นับจากทั้งชุด ไม่ใช่แค่หน้าปัจจุบัน** เช่น `counts` (จำนวนตามสถานะ
ของ `/api/orders`) · `summary` (ยอดรวมคลังของ `/api/admin/inventory`) · `unreadCount` ของ `/api/notifications`
· `range` (ช่วงวันที่ตีความแล้ว) ของ `/api/admin/logs`

**การเรียงลำดับและการกรองเกิดก่อนการแบ่งหน้าเสมอ** — เรียงเฉพาะแถวในหน้าปัจจุบันคืออันดับปลอม
ที่ผู้ใช้จับไม่ได้ · `sort` รับเฉพาะค่าใน whitelist ไม่เคยต่อสตริงจาก query ลง SQL

### ตัวเลข วันเวลา และไฟล์

- **เงินเป็น `number` ไม่ใช่สตริง** — `Decimal` ของ Prisma ถูกแปลงที่ชั้น DTO (ไม่งั้นกลายเป็นสตริงใน JSON)
- **ราคาและสต็อกคิดที่ server เท่านั้น** client ส่งได้แค่ `variantId` + `quantity`
  ฟิลด์ราคาที่ client แนบมาถูก Zod ตัดทิ้ง (มีเทสต์ยืนยันทุกจุดที่เกี่ยวกับเงิน)
- **เวลาเป็น ISO 8601** · คอลัมน์เวลาในฐานข้อมูลเป็น `timestamp without time zone` ที่เก็บหน้าปัด **UTC**
  การตัดวันของรายงานทำตามเวลาร้าน (`Asia/Bangkok`) — อ่านกับดักทั้งหมดได้ในหัวข้อ Analytics ของ CLAUDE.md
- **วันเกิดเป็น `YYYY-MM-DD`** (คอลัมน์ `@db.Date`) ไม่ใช่ timestamp
- **เส้นทางที่ส่งไฟล์** (`/export/*`, `/analytics/export`, `/logs/export`) คืนไฟล์ตรง ๆ ไม่ใช่ JSON
  → `format=csv` ได้ `text/csv` ที่ **นำหน้าด้วย UTF-8 BOM** (ไม่งั้น Excel บน Windows อ่านภาษาไทยเพี้ยน)
  · `format=xlsx` ได้ไฟล์ Excel · ชื่อไฟล์อยู่ใน `Content-Disposition`

## วิธีอ่านตาราง

คอลัมน์ **ต้องมี** บอกด่านที่ต้องผ่านก่อนถึง controller:

| ค่าที่เขียน       | ความหมาย                                                                     |
| ----------------- | ---------------------------------------------------------------------------- |
| `สาธารณะ`         | เรียกได้โดยไม่ล็อกอิน                                                        |
| `ล็อกอินถ้ามี`    | guest เรียกได้ แต่ถ้ามี session ระบบจะรู้ว่าเป็นใครและตอบข้อมูลรายบุคคลเพิ่ม |
| `ล็อกอิน`         | ต้องล็อกอิน ไม่ต้องมีสิทธิ์พิเศษ — ขอบเขตคือ "เป็นเจ้าของแถวไหม"             |
| `` `perm:name` `` | ต้องล็อกอินและมีสิทธิ์นี้ (หลายตัว = ต้องมีครบทุกตัว)                        |
| `· 20/นาที`       | ต่อท้ายเมื่อเส้นทางนั้นถูกจำกัดความถี่แบบเข้ม                                |

ทุกเส้นทางใต้ `/api/admin` **ต้องเป็น `EMPLOYEE` / `ADMIN` / `SUPER_ADMIN` เพิ่มอีกชั้น** นอกจากสิทธิ์ที่ระบุ
(`requireStaff()` ที่ระดับ router) — สิทธิ์จริงแต่ละบทบาทมีอะไรบ้างดูจาก seed ของฐานข้อมูล ไม่ได้ hard-code ในโค้ด

## ระบบ

| Method | Path      | ต้องมี  | รายละเอียด                                                                     |
| ------ | --------- | ------- | ------------------------------------------------------------------------------ |
| GET    | `/health` | สาธารณะ | สถานะเซิร์ฟเวอร์ + ผลเช็คการเชื่อมต่อฐานข้อมูล (ใช้กับ healthcheck ของ Docker) |
| GET    | `/api`    | สาธารณะ | สารบัญ API — จำนวน endpoint และเมธอดของทุกกลุ่ม **อ่านจาก router จริง**        |

`GET /api` แยก 3 รายการออกจากกันชัดเจน: `groups` (มีอยู่จริง เรียกได้เลย) · `external` (อยู่บน Next.js
ไม่ใช่ Express) · `planned` (**ยังไม่มี — เรียกแล้วได้ 404**) เดิมสามอย่างนี้ปนกันอยู่ในรายการเดียว
โดยมีแค่ฟิลด์ `status` กำกับ ซึ่งอ่านผ่าน ๆ แล้วเข้าใจว่าเรียกได้ทั้งหมด

| Method | Path                                         | ต้องมี  | รายละเอียด                                                                           |
| ------ | -------------------------------------------- | ------- | ------------------------------------------------------------------------------------ |
| GET    | `/api/users/me`                              | ล็อกอิน | ตัวตนย่อ ๆ ของผู้ใช้ปัจจุบัน + บทบาทและสิทธิ์                                        |
| GET    | `/api/users/me/profile`                      | ล็อกอิน | ชื่อ เบอร์โทร วันเกิด และสวิตช์การแนะนำแบบ personalized                              |

| DELETE | `/api/users/me/addresses/:addressId`         | ล็อกอิน | ลบแบบ soft delete · ถ้าลบอันที่เป็นค่าเริ่มต้น ระบบเลื่อนอันอื่นขึ้นแทน              |

ไม่มีเส้นทางใดรับ `userId` จาก client — เจ้าของข้อมูลมาจาก session เท่านั้น จึงไม่มีช่องอ่าน/แก้ข้อมูลของคนอื่น

## สินค้า — `/api/products` · `/api/categories`

| Method | Path                          | ต้องมี       | รายละเอียด                                                                           |
| ------ | ----------------------------- | ------------ | ------------------------------------------------------------------------------------ |
| GET    | `/api/products`               | สาธารณะ      | สินค้าสำหรับหน้าแรก — `sort` รับ `newest`, `discount`, `bestselling`, `popular`      |
| GET    | `/api/products/search`        | สาธารณะ      | หน้า `/shop` — ค้นหา กรอง เรียง แบ่งหน้า (ทุกเงื่อนไขอยู่ใน query string)            |
| GET    | `/api/products/filters`       | สาธารณะ      | ตัวเลือกของตัวกรอง + จำนวนที่นับด้วย **เงื่อนไขเดียวกับการค้นหา**                    |
| POST   | `/api/products/availability`  | สาธารณะ      | ด่านจริงก่อน "เพิ่มลงตะกร้า" — ตอบจำนวนที่ซื้อได้จริงต่อ variant                     |
| GET    | `/api/products/:slug/reviews` | ล็อกอินถ้ามี | รีวิวที่อนุมัติแล้ว + คะแนนเฉลี่ย · คนที่ล็อกอินได้รีวิวตัวเองที่ยังรอตรวจกลับไปด้วย |
| GET    | `/api/products/:slug`         | สาธารณะ      | รายละเอียดสินค้า + ตัวเลือกสี/ไซซ์ · **เพิ่ม `viewCount` ที่ฐานข้อมูล**              |
| GET    | `/api/categories`             | สาธารณะ      | หมวดหมู่แบบต้นไม้พร้อมจำนวนสินค้า                                                    |

**สถานะสต็อกทุกที่คิดจาก `quantity − reservedQuantity` ไม่ใช่ `Product.totalStock`**
`totalStock` คือ cache ของของที่อยู่ในคลัง ซึ่ง **ไม่เท่ากับของที่ขายได้** (ดูกฎ STEP 15 ใน CLAUDE.md)
แหล่งความจริงเดียวคือ [availability.ts](../backend/src/models/availability.ts)

## ข้อจำกัดที่รู้อยู่

1. **ยังไม่มี OpenAPI / Swagger** — แผนผังใน [api-map.ts](../backend/src/models/api-map.ts) มีข้อมูล
   ครบพอจะสร้าง OpenAPI ได้ (เมธอด · path · ด่าน) แต่ยัง **ไม่มี schema ของ request/response**
   ในรูปแบบที่เครื่องอ่านได้ ซึ่งต้องดึงจาก Zod validator ของแต่ละเส้นทาง — เป็นงานที่ควรทำพร้อม
   การเปิด API ให้คนนอกใช้ ไม่ใช่ตอนที่ผู้ใช้เดียวคือเว็บของเราเอง
2. **ไม่มีเวอร์ชันใน path** — ยังไม่จำเป็นเพราะผู้เรียกมีรายเดียว แต่ถ้าเปิดให้ภายนอกใช้
   ต้องมีก่อนเปลี่ยนอะไรที่ทำให้ของเดิมพัง
3. **`viewCount` นับเฉพาะตอนเปิดอ่านฉบับเต็ม** ไม่ได้นับตอนเห็นการ์ดในรายการ — ตัวเลขจึงหมายถึง
   "กดอ่านเต็ม ๆ กี่ครั้ง" ไม่ใช่ "impression" · หน้าเว็บต้องเขียนกำกับให้ตรงความหมายนี้
4. **rate limit เก็บ state ในหน่วยความจำ** — รีสตาร์ตแล้วโควตารีเซ็ต และใช้ร่วมกันหลาย instance
   ไม่ได้ (STEP 34)
5. **`/api/auth/*` ไม่ผ่าน rate limiter ของเรา** เพราะอยู่บน Next (STEP 38 ต้องทำที่ edge)
