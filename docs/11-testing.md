### เลือกองค์ประกอบด้วย role ไม่ใช่ class

`getByRole('button', { name: 'เพิ่มจำนวน' })` ผูกกับ **ชื่อที่ screen reader อ่านได้**
ถ้าใครลบ `aria-label` ทิ้ง เทสต์ล้มทันที → เทสต์ชุดนี้จึงกันกฎข้อ 12 (accessibility) ไปด้วยโดยปริยาย
ไม่ใช่แค่กันตรรกะ · ห้ามเลือกด้วย `querySelector('.btn-brand')` เพราะ class เปลี่ยนได้โดยที่ UI ยังถูก

## บั๊กที่เจอจากการเขียนเทสต์ (ทั้ง 5 ข้อคือของจริง แก้แล้ว)

### 1. ช่องจำนวนในตะกร้าโชว์เลขที่ไม่ตรงกับตะกร้า

[cart-item-row.tsx](../frontend/src/features/cart/components/cart-item-row.tsx) ใช้ช่องแบบ
uncontrolled (`defaultValue` + `key`) โดยเจตนา เพื่อให้พิมพ์ได้โดยไม่ยิง API ทุกตัวอักษร
แต่ถ้าเลขที่ปัดแล้ว **เท่ากับจำนวนเดิม** จะไม่มีการยิง API และไม่มี re-render มาล้างเลขที่พิมพ์ทิ้ง

> ของเหลือ 3 ในตะกร้ามี 3 · พิมพ์ 9 แล้วออกจากช่อง → **ช่องค้างเลข 9** แต่ยอดรวมข้างล่าง
> เป็นของ 3 ชิ้น = สองตัวเลขขัดกันบนหน้าเดียว และลูกค้าเชื่อเลขในช่องที่ตัวเองพิมพ์

**แก้:** เขียนค่าที่ใช้จริงกลับลงช่องเองทุกครั้งใน `onBlur`

### 2. ปรับสต็อกโทษลูกค้าที่ไม่มีอยู่

ตัดของออกมากกว่าที่มีในคลังทำให้ยอดหลังปรับติดลบ ซึ่งเข้าเงื่อนไข `belowReserved` ด้วยเสมอ
(เพราะ `reserved ≥ 0`) ข้อความจึงออกมาว่า

> "ยอดหลังปรับ (-5 ชิ้น) ต่ำกว่าของที่ลูกค้าจองไว้ (**0 ชิ้น**) — ต้องจัดการคำสั่งซื้อเหล่านั้นก่อน"

แอดมินจะไปไล่หาคำสั่งซื้อที่ไม่มีอยู่จริง **แก้:** แยก `overCutting` ออกมาพร้อมข้อความที่บอกสาเหตุจริง

### 3. ส่งของได้โดยไม่มีเลขพัสดุ

[order-status-form.tsx](../frontend/src/features/admin/components/order-status-form.tsx)
ให้กดบันทึก "กำลังจัดส่ง" ได้ทั้งที่ช่องขนส่งและเลขพัสดุยังว่าง (ทั้งสองช่องมีดอกจันกำกับว่าบังคับ)
server ปฏิเสธถูกต้องตามกฎ STEP 13 ข้อ 2 แต่แอดมินได้ 422 กลับมาโดยไม่รู้ว่าช่องไหนขาด
**แก้:** เพิ่ม `trackingReady` — ด่านจริงยังอยู่ที่ server เหมือนเดิม อันนี้คือการไม่ยิงคำขอที่รู้อยู่แล้วว่าจะถูกปฏิเสธ

### 4. เหตุผลระดับช่องถูกทิ้งในฟอร์มฝั่งลูกค้า

`describeApiError()` ที่ต่อ `details` เข้ากับข้อความ (กฎ STEP 26 ข้อ 10) **มีแต่หลังบ้านที่ใช้**
เพราะเดิมอยู่ใน `features/admin/lib/` · ฟอร์มที่อยู่ · ข้อมูลส่วนตัว · รีวิว · เปลี่ยนสถานะคำสั่งซื้อ ·
ระงับบัญชี · ตรวจรีวิว อ่าน `error.message` ตรง ๆ แล้วลูกค้าเห็นแค่ "ข้อมูลที่ส่งมาไม่ถูกต้อง"
ซึ่งทำตามไม่ได้ **แก้:** ย้ายเป็นของกลางที่ [lib/api-error-text.ts](../frontend/src/lib/api-error-text.ts)
แล้วใช้กับฟอร์มทั้ง 6 ที่

### 5. พิมพ์ราคาผิดหนึ่งตัวอักษร = ราคาที่เก็บเงินเปลี่ยน (บั๊กเรื่องเงิน)

```js
JSON.stringify({ price: Number("abc") }); // → {"price":null}
```

`NaN` กลายเป็น `null` ตอน serialize ซึ่ง API อ่านว่า **"ล้างราคาของตัวเลือกนี้"**
ตัวเลือกจึงกลับไปใช้ราคาสินค้าแม่ **โดยหน้าจอตอบว่า "บันทึกราคาและบาร์โค้ดของตัวเลือกแล้ว"**
เรื่องเดียวกันเกิดกับ `salePrice` (ส่วนลดหายเงียบ ๆ) และ `initialStock`

**แก้:** ตรวจ `MONEY_PATTERN` / `INTEGER_PATTERN` ก่อนเรียก `Number()` โดย
**ใช้กฎชุดเดียวกับฟอร์มสินค้า** ([features/admin/lib/product-form.ts](../frontend/src/features/admin/lib/product-form.ts))
ไม่เขียนกฎใหม่ซ้ำ

> **บทเรียนที่ใช้ต่อได้:** ทุกที่ที่มี `Number(ค่าที่ผู้ใช้พิมพ์)` แล้วส่งขึ้น API
> ต้องตรวจรูปแบบก่อน ไม่งั้นได้ `null` ที่มีความหมายว่า "ลบค่านี้"

## กฎที่ห้ามละเมิด

1. **เทสต์ใหม่ทุกตัวต้องพิสูจน์ว่าไม่ว่างเปล่า** — แก้โค้ดให้พังตรงจุดที่เทสต์อ้างว่าตรวจ
   แล้วดูว่ามันล้มจริง จากนั้นคืนโค้ด · เทสต์ที่ผ่านทั้งตอนโค้ดถูกและตอนโค้ดผิดคือเทสต์ที่โกหก
   (ทำไว้ทุกไฟล์ในชุดนี้ — บั๊กทั้ง 5 ข้อข้างบนเจอเพราะเทสต์ล้ม **ก่อน** จะมีการแก้โค้ด)
2. **เทสต์คอมโพเนนต์ตรวจพฤติกรรม ไม่ใช่ตรวจว่าเรนเดอร์ผ่าน** — `render()` แล้วไม่ error
   ไม่ได้บอกอะไรเลย · ต้องกดแล้วดูว่า **ส่งอะไรขึ้น API** และ **ผู้ใช้เห็นอะไร**
3. **ห้าม mock ตรรกะของเราเอง** — ปลอมได้แค่เปลือกของ Next กับ `*.service.ts` ที่ยิง HTTP
4. **เลือกองค์ประกอบด้วย role + ชื่อที่ผู้ใช้อ่านได้** ห้ามใช้ class หรือ test id
5. **หน้าต่างใหม่ทุกอันต้องผ่าน [tests/dialog.test.ts](../frontend/tests/dialog.test.ts)**
   ซึ่งอ่านซอร์สแล้วบังคับกฎ 5 ข้อของหน้าต่าง (aria-modal · ชื่อ · Esc + ถอด listener ·
   ล็อก scroll แล้วคืนค่าเดิม · พื้นหลังเป็น element แยกที่ `aria-hidden`)
   คู่กับ [mobile-menu.test.tsx](../frontend/src/components/layout/mobile-menu.test.tsx)
   ที่ยืนยันว่าแพตเทิร์นอ้างอิง **ทำงานจริง** — อ่านซอร์สบอกได้แค่ว่า "เขียนไว้"
6. **หน้าเพจใหม่ต้องเพิ่มใน `ROUTES` ของ `scripts/audit-responsive.mjs`** (กฎ STEP 31 ข้อ 9)
   เพราะหน้าเพจไม่มีเทสต์คอมโพเนนต์ — ตัวที่ครอบหน้าเพจคือ audit 3 ตัวนั้น
