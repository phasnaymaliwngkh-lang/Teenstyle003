# 18 — Advanced Search (STEP 45)

> ค้นหาทั้งร้านจากช่องเดียว · พิมพ์เป็นภาษาคนได้ · บอกเสมอว่าเข้าใจว่าอะไร · และสิ่งที่ยังไม่ได้ทำ

```
/search?q=…                    → ผลค้นหา: สินค้า + ลุค + คำตอบจากคลังความรู้ + "คุณหมายถึง…"
                                 ช่องค้นหาแนะนำระหว่างพิมพ์ · ค้นล่าสุด (เก็บในเครื่องนี้เท่านั้น)
/shop?q=…                      → ค้นหลายคำได้แล้ว (ทุกคำต้องตรง) — ใช้ตรรกะเดียวกับ /search

GET /api/search?q=&literal=&sort=&page=&limit=   (สาธารณะ)
GET /api/search/suggest?q=                       (สาธารณะ)
```

## จุดเริ่มต้น

- `/search` เป็นหน้า placeholder (ComingSoon) — ไอคอนแว่นขยายบน navbar ทุกหน้าพาไปหน้าที่ใช้ไม่ได้
- ช่องค้นหาของ `/shop` เทียบ **ทั้งประโยคเป็นก้อนเดียว** — "เสื้อ ดำ" ต้องอยู่ติดกันในชื่อสินค้าจึงเจอ
  และค้นแค่ชื่อกับ SKU · tag ต้องตรงทั้งคำ · ไม่ escape `%` `_` (พิมพ์ `%` ได้ทุกสินค้า)
- **คอมเมนต์ 3 ที่และเอกสารฐานข้อมูลบอกว่าการค้นหา "ใช้ GIN index (pg_trgm) ที่สร้างไว้ใน STEP 2"**
  — index นั้นถูก `prisma migrate dev` ลบไปตั้งแต่ migration ถัดมา (ไม่อยู่ใน schema) และ STEP 34 วัดแล้วว่า
  ไม่ช่วยที่ 5,000 สินค้า จึงไม่ได้สร้างกลับ · แก้ข้อความให้ตรงความจริงแล้ว

## ตีความคำค้น — [models/search.model.ts](../backend/src/models/search.model.ts)

"เสื้อสีดำราคาไม่เกิน 500 บาท" → คำค้น `เสื้อ` + สีดำ + ราคาไม่เกิน 500

| พิมพ์                                                          | กลายเป็น                   |
| -------------------------------------------------------------- | -------------------------- |
| สีดำ · ดำ · black · สีม่วง (→ ม่วงลาเวนเดอร์) · pink           | ตัวกรองสี (ตัวเลือกสินค้า) |
| ไซซ์ M · XL · ฟรีไซซ์ · เบอร์ 38                               | ตัวกรองไซซ์                |
| ไม่เกิน 500 · ต่ำกว่า 2k · 500-1,000 · 1,000 ขึ้นไป · ราคา 500 | ตัวกรองราคาที่จ่ายจริง     |
| พร้อมส่ง · มีของ                                               | เฉพาะของที่ขายได้จริง      |
| ลดราคา · sale                                                  | เฉพาะที่ลดราคา             |
| คำอื่น                                                         | คำค้น — ทุกคำต้องตรง       |

**กฎที่ห้ามละเมิด**

1. **ตีความจากคำศัพท์ของร้านเท่านั้น** (สีและไซซ์จากฐานข้อมูล) — ไม่ใช้ AI ไม่เดาเงื่อนไข
   คำเรียกสีพื้นฐาน ("ม่วง" "pink") เป็นพจนานุกรมภาษาที่ใช้ **จับคู่กับสีที่ร้านมีจริง** เท่านั้น
2. **ทุกเงื่อนไขที่ตีความได้ต้องแสดงและยกเลิกได้** — แถบ "เข้าใจว่า: …" + ลิงก์ "ค้นตามตัวอักษร" (`literal=true`)
   · ราคาที่ตีความจาก "ต่ำกว่า X" หรือ "ราคา X" เขียนป้ายว่า **"ราคาไม่เกิน X บาท"** ตามที่ใช้กรองจริง
3. **สีที่ร้านไม่มี → ผลว่างพร้อมบอกเหตุผล** ("ร้านยังไม่มีสินค้าสีแดง") **ไม่แสดงสินค้าสีอื่นแทน**
   และไม่แสดงลุค (ลุคไม่มีตัวกรองสี) · ช่วงราคาที่ขัดกันเองก็เช่นกัน
4. **หมวดหมู่และแบรนด์ไม่ถูกแปลงเป็นตัวกรองบังคับ** — "เสื้อแจ็คเก็ต" ถ้าบังคับหมวด "เสื้อ"
   แจ็คเก็ตในหมวด "เสื้อคลุม" จะหาย · ชื่อหมวด/tag ใช้ **ตัดคำภาษาไทยที่พิมพ์ติดกัน** แล้วให้แต่ละคำ
   ไปจับชื่อ · SKU · คำอธิบาย · tag · ชื่อหมวด (รวมหมวดแม่) · ชื่อแบรนด์เอง
5. **ภาษาไทยไม่มีช่องว่างระหว่างคำ** — กับดักที่เจอระหว่างเขียน (มีเทสต์ทุกข้อ):
   - คำหยุด ("ที่") ซ้อนอยู่ในคำอื่น ("เที่ยว") → ตัดคำหยุดเฉพาะหัว/ท้าย และไม่ตัดถ้าจะเหลือเศษตัวเดียว
   - สระบน/ล่างและวรรณยุกต์เป็น Unicode "mark" ไม่ใช่ "letter" → การเล็มอักขระท้ายคำต้องนับ `\p{M}`
     ไม่งั้นไม้โทท้าย "ฮู้ดดี้" หาย
   - "น้ำเงิน" ต้องจับก่อน "เงิน" (ยาวสุดก่อน) · คำที่มีความหมายอื่นบ่อย ("เงิน" "ทอง") ต้องมีคำว่า "สี" นำหน้า
   - ตัวเลขล้วนต้องมี "ไซซ์/เบอร์" นำหน้าจึงเป็นไซซ์ (ไม่ชนกับราคา) · "k" ต้องติดตัวเลข ("500 kids" ไม่ใช่ 500,000)
6. **ตีความแล้วไม่เหลืออะไร → ค้นข้อความดิบ** — ไม่ใช่ "ไม่มีเงื่อนไข = ทุกสินค้าในร้าน"

## ค้นข้อความ — [shop.service.ts](../backend/src/services/shop.service.ts) `termCondition`

- **หลายคำ ทุกคำต้องตรง** (คั่นด้วยช่องว่าง · ไม่เกิน 6 คำ) — ใช้ทั้ง `/api/products/search` และ `/api/search`
  · การค้นลุคใช้กติกาเดียวกัน
- **escape `%` `_` `\`** ก่อนใส่ ILIKE — ⚠️ `contains` ของ Prisma **ไม่ escape ให้** (`contains: '%'` ได้ทุกแถว)
  ช่องค้นหาในหลังบ้านที่ใช้ `contains` จึงยังตีความ `%` เป็น wildcard อยู่ (ผลกว้างเกิน ไม่ใช่ช่องโหว่ · ยังไม่ได้แก้)
- ทุกขาเป็นเงื่อนไขของตาราง Product เอง (subquery ของหมวด/แบรนด์ไม่อ้างแถวนอก) — ไม่ใช่ OR ข้ามตาราง (กฎ STEP 34 ข้อ 2)
- การเรียง `relevance` (ค่าเริ่มต้นของ `/search`) = `word_similarity(คำค้น, ชื่อสินค้า)` ของ pg_trgm

## "คุณหมายถึง…"

เมื่อไม่พบสินค้า: หาคำที่ใกล้เคียงที่สุด (`word_similarity ≥ 0.4`) จาก **ชื่อสินค้า · tag · ชื่อหมวดที่มีจริง** — 3 คำ
· มีเทสต์ยืนยันว่า **ทุกคำที่แนะนำค้นแล้วเจอของจริง** (แนะนำคำที่ค้นแล้วว่างอีกคือวนลูปให้ลูกค้า)

⚠️ **ขึ้นกับ locale ของฐานข้อมูล** — pg_trgm แยกตัวอักษรตาม ctype · ฐานข้อมูลเครื่องนี้ (`Thai_Thailand.874`)
ตรวจแล้วว่าใช้กับภาษาไทยได้ (`กระโปง` → `กระโปรง`) · ฐานข้อมูลที่ ctype ไม่นับอักษรไทยเป็นตัวอักษร
จะได้คะแนน 0 แล้ว **ไม่แนะนำอะไรเลย** (ไม่ใช่แนะนำผิด) — ตรวจเครื่อง production ด้วย `SELECT show_trgm('เสื้อ')`

## หน้า `/search` และช่องค้นหา

- **ช่องค้นหาเป็น combobox ตาม WAI-ARIA** — ลูกศรขึ้น/ลง · Enter · Esc · `aria-activedescendant` · ประกาศจำนวนคำแนะนำ
- พิมพ์แล้วหน่วง 250ms ค่อยถาม (`hooks/use-debounce.ts`) · คำขอเก่าถูกยกเลิก · **คำแนะนำของคำเก่าไม่โผล่กับคำใหม่**
- **สินค้าในกล่องแนะนำคือ 5 ชิ้นแรกของผลค้นหาจริง** (มีเทสต์เทียบ) ไม่ใช่รายการแยกที่คิดคนละแบบ
- **ค้นล่าสุดเก็บใน `localStorage` ของเครื่องนี้เท่านั้น** — ไม่ส่งขึ้นเซิร์ฟเวอร์ (ประวัติการค้นหาคือข้อมูลส่วนบุคคล ·
  STEP 53) · ทุกการอ่านเขียนครอบ try/catch · กล่องบอกตรง ๆ ว่าเก็บในเครื่องนี้ และมีปุ่มล้าง
- **ไม่มี "คำค้นยอดนิยม"** — ระบบไม่ได้เก็บสถิติการค้นหา จึงแนะนำ **หมวดที่มีจริง** แทน (ไม่แต่งความนิยม)
- ผลค้นหา: แถบ "เข้าใจว่า" · สินค้า (การ์ดชุดเดียวกับ `/shop`) · เรียงได้ · แบ่งหน้า ·
  **"กรองต่อที่หน้าร้าน"** = เงื่อนไขชุดเดียวกันใน `/shop` (`shopQuery` — มีเทสต์ยืนยันว่าได้สินค้าชุดเดียวกัน) ·
  ลุคที่เกี่ยวข้อง · คำตอบจากคลังความรู้ (ข้อคำถามที่ตรงกับคำค้นที่สุด ไม่หยิบข้อแรกมาให้ดูเหมือนตรง)
- `noindex, follow` — หน้าผลค้นหาสร้างได้ไม่จำกัด ห้ามขึ้นดัชนี แต่บ็อตตามลิงก์ไปหน้าสินค้าได้ (กฎ STEP 33 ข้อ 6)
- `WebSite` JSON-LD ประกาศ `SearchAction` แล้ว (เป็นความจริงของเว็บแล้ว · Google เลิกแสดงช่องค้นหาใต้ผลลัพธ์ตั้งแต่ปลายปี 2024)

## บั๊กของผมเองที่เทสต์จับได้ระหว่างทาง

`splitSearchTerms` ใช้ `split(/s+/)` แทน `split(/\s+/)` — backslash หายตอนแก้ไฟล์ด้วยสคริปต์ผ่าน shell
ผลคือ `/shop` ตัดคำที่ตัวอักษร "s" แทนช่องว่าง ("เสื้อ oversize" → "เสื้อ o" · "ver" · "ize") · เทสต์ "/search = /shop"
และ "/shop หลายคำ" ล้มทันที · ไล่ตรวจทั้งโปรเจกต์แล้วว่าไม่มี regex ที่ backslash หายตกค้างที่อื่น

## ที่ยังไม่ได้ทำ (บอกไว้ตรง ๆ)

- **ยังไม่มีสถิติคำค้นยอดนิยม / คำค้นที่ไม่เจออะไร** — ต้องเก็บ log การค้นหา (ข้อมูลส่วนบุคคล → นโยบาย STEP 53)
  ยังไม่มี STEP ไหนรับงานนี้ไว้
- **ยังไม่มีคำพ้องความหมายข้ามภาษา** ("เกาหลี" ไม่จับ tag "korean") — ต้องมีตารางคำพ้องที่ร้านดูแลเอง
- **ยังไม่มีหน้าบทความคลังความรู้รายชิ้น** — ผลค้นหาแสดงคำตอบในหน้าเลย และลิงก์ไป `/faq`
- **ตัดคำไทยด้วยคำที่ร้านรู้จักเท่านั้น** (ชื่อหมวด · tag) ไม่ใช่ตัวตัดคำภาษาไทยเต็มรูปแบบ —
  คำที่พิมพ์ติดกันโดยไม่มีคำที่รู้จักคั่นจะถูกค้นเป็นก้อนเดียว
- **ช่องค้นหาในหลังบ้านที่ใช้ `contains` ของ Prisma ยังไม่ escape `%` `_`** (ดูด้านบน)
- `ProductSort` ฝั่งหน้าร้าน (`/shop`) ยังไม่มีตัวเลือก "ตรงที่สุด" — มีเฉพาะที่ `/search`
