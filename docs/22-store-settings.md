# 22 — Store Settings (STEP 49)

> ร้านแก้ข้อมูลร้านเองได้ · ทุกที่ที่ลูกค้าเห็นและที่ AI ตอบใช้ค่าชุดเดียวกัน ·
> ช่องทางที่ร้านไม่มีไม่ถูกพูดถึงที่ไหนเลย · ร้านลดวันคืนสินค้าลงแล้วไม่มีใครเสียสิทธิ์ย้อนหลัง

```
/admin/settings        → คำอธิบายร้าน · อีเมล · เบอร์โทร · โซเชียล 4 แพลตฟอร์ม · เวลาทำการ · วันส่งของ ·
                         เวลาตัดรอบ · จำนวนวันที่คืนได้ · ยอดสูงสุดของ COD   (settings:manage)
/about                 → หน้าเกี่ยวกับเราจริง (เดิมเป็นหน้า "เร็ว ๆ นี้")
footer ทุกหน้า · หน้าแรก · หน้าฝ่ายบริการลูกค้า · structured data ของร้าน → อ่านจากค่าชุดเดียวกัน

GET   /api/store             ← สาธารณะ · ข้อมูลร้านที่หน้าร้านใช้
GET   /api/admin/settings    PATCH /api/admin/settings   (settings:manage)
```

ค่าส่งไม่อยู่ที่นี่ — แก้ที่ `/admin/shipping` (STEP 44 · [17-shipping.md](17-shipping.md))

## จุดเริ่มต้น

- **footer โฆษณาเบอร์โทร `02-000-0000` (พร้อมลิงก์ `tel:`) ที่ร้านไม่มี** — ทั้งที่ `config/store.ts` บอกไว้แล้วว่า
  "ร้านยังไม่เปิดบริการทางโทรศัพท์" และ STEP 21 เคยลบเบอร์สมมติออกจากบทความไปแล้วรอบหนึ่ง
- **ปุ่มโซเชียลทั้ง 4 ปุ่มลิงก์ไป `instagram.com` · `tiktok.com` · `facebook.com` · `line.me` เฉย ๆ** —
  หน้าแรกของแพลตฟอร์ม ไม่ใช่โปรไฟล์ของร้าน
- **ข้อมูลร้านพิมพ์แยกไว้หลายที่**: `config/store.ts` (เวลาทำการ · ช่องทางติดต่อ · เวลาตัดรอบ · วันส่งของ · วันคืนสินค้า) ·
  `config/payment.ts` (ยอดสูงสุดของ COD) · footer (อีเมล · เบอร์ · เวลาทำการชุดที่สาม) · หน้าแรกและหน้าฝ่ายบริการลูกค้า
  (`"คืนได้ 7 วัน"`) — ร้านแก้อะไรไม่ได้เลยถ้าไม่แก้โค้ด
- **บทความคลังความรู้ประกอบค่าเหล่านี้ลงข้อความตอน seed** — แก้ค่าในโค้ดแล้วบทความในฐานข้อมูลไม่เปลี่ยนตาม
  และ **สถานะช่องทางชำระเงินถูกแช่ไว้ตั้งแต่ตอน seed**: ถ้าเปิด Stripe ทีหลัง บทความยังบอกว่า "ยังไม่เปิดให้ใช้งาน
  — ยังไม่ได้ตั้งค่า STRIPE_SECRET_KEY…" ตลอดไป
- `/about` เป็นหน้า "เร็ว ๆ นี้" · structured data ของร้านไม่มีอีเมลเพราะ "ต้องมาจาก config ของ backend"

## ข้อตกลงหลัก

**ข้อมูลร้านมีแถวเดียว (`StoreSetting` · `id = 1` · CHECK ในฐานข้อมูล) และทุกที่อ่านผ่าน `getStoreSettings()`**
([services/store-settings.service.ts](../backend/src/services/store-settings.service.ts)) — อ่านใหม่ทุกคำขอ (แถวเดียว ~1ms)
จึงไม่มีสำเนาที่ค้างค่าเก่า · กฎล้วนอยู่ที่ [models/store-settings.model.ts](../backend/src/models/store-settings.model.ts)

| ใครใช้                                | ใช้อะไร                                                                             |
| ------------------------------------- | ----------------------------------------------------------------------------------- |
| footer · `/about` · หน้าแรก · หน้า CS | `GET /api/store` (แคช 60 วินาที เหมือนข้อมูลหน้าร้านอื่น)                           |
| บทความคลังความรู้                     | ตัวแปร `{{store.*}}` `{{returns.*}}` `{{payment.*}}` แทนค่าทุกครั้งที่อ่าน          |
| AI Customer Service                   | `getStorePolicyContent()` อ่านแถวเดียวกัน                                           |
| ช่องทางชำระเงิน                       | `paymentMethods(total, codMaxTotal)` — **ไม่มีค่าเริ่มต้น** ลืมส่ง = คอมไพล์ไม่ผ่าน |
| การสร้างคำสั่งซื้อ                    | snapshot จำนวนวันที่คืนได้ลง `Order.returnWindowDays` (ในทรานแซกชันเดียวกัน)        |
| สิทธิ์ขอคืนสินค้า                     | `effectiveReturnWindowDays(ของใบนั้น, ค่าปัจจุบัน)`                                 |
| structured data ของร้าน               | อีเมล · เบอร์ · `sameAs` เฉพาะที่ตั้งไว้                                            |

migration ใส่ค่าตั้งต้นเป็น **ค่าเดิมที่โค้ดใช้อยู่ทุกตัว** — ยกเว้นสิ่งที่ไม่เคยจริง: เบอร์โทร (`null`) และโซเชียลทั้ง 4 (`null`)

## กฎที่ห้ามละเมิด

1. **ช่องที่เป็น `null` = ร้านไม่มีช่องทางนั้น → ไม่แสดงที่ไหนเลย** (footer · `/about` · บทความ · AI · structured data)
   ห้ามเติมค่าสมมติให้หน้าดูครบ · PATCH ส่ง `null` เพื่อล้าง — **สตริงว่างถูกปฏิเสธ** (ฟอร์มที่ลืมแปลง `""` เป็น `null`
   จะได้ลิงก์ว่างโผล่ใน footer)
2. **ลิงก์โซเชียลต้องเป็นโปรไฟล์ของร้านบนโดเมนของแพลตฟอร์มนั้น** (`socialUrlProblem`) — https เท่านั้น ·
   โดเมนตรงตัว (`instagram.com.evil.example` ไม่ผ่าน) · **ต้องมี path** (หน้าแรกของแพลตฟอร์มไม่ผ่าน)
   · ลิงก์ถูกแสดงเป็นปุ่มทุกหน้าและถูกประกาศเป็น `sameAs` ของร้าน
3. **ค่าที่แก้ได้ตอน runtime และไปอยู่ในบทความ ต้องเป็นตัวแปร** (กฎ STEP 44 ข้อ 2) — migration
   `20261008121000_store_settings_article_tokens` แทนเฉพาะวลีที่มีค่าเหล่านี้ใน 3 บทความ (บทความที่แอดมินเขียนใหม่ไม่ถูกทับ ·
   วลีที่ไม่มีแล้วก็ไม่ถูกแทน) และทุกตัวแปรแทนค่าออกมาเป็นข้อความเดิมเป๊ะ ณ วันที่ย้าย
4. **จำนวนวันที่คืนได้: คำสั่งซื้อใหม่ snapshot ค่าตอนสั่ง · สิทธิ์ใช้ค่าที่ยาวกว่า** ระหว่างของใบนั้นกับค่าปัจจุบัน
   — ร้านลดวันลง ใบที่สั่งไปแล้วยังได้ตามที่ตกลงตอนซื้อ · ร้านขยายวัน ใบเดิมได้ด้วย (บทความประกาศค่าใหม่ให้ทุกคนอ่าน
   ลูกค้าเก่าต้องไม่ถูกปฏิเสธด้วยค่าเก่า) · ข้อความ "เลยกำหนด" บอกจำนวนวันของใบนั้น
   · `Order.returnWindowDays` **ไม่มีค่าเริ่มต้นโดยเจตนา** — ตัวสร้างคำสั่งซื้อที่ลืมอ่านการตั้งค่าคอมไพล์ไม่ผ่าน
5. **ยอดสูงสุดของ COD ตัดสินจากค่าปัจจุบันทุกครั้ง** ทั้งหน้าชำระเงินและด่านจ่ายเงินจริง — ใช้กับใบที่ยังไม่ชำระด้วย
   (เป็นการคุมความเสี่ยงของร้าน ณ ตอนรับเงิน ไม่ใช่สัญญาตอนสั่ง)
6. **คำอธิบายร้านห้ามมีจำนวนเงิน** (กฎเดียวกับคำอธิบายวิธีจัดส่งของ STEP 44) — แสดงทุกหน้า ตัวเลขจะค้างค่าเก่า
7. **บันทึกเฉพาะช่องที่ค่าเปลี่ยนจริง** · ส่งค่าเดิมซ้ำไม่เขียนทั้งแถวและ log · ล็อกแถว `FOR UPDATE` ก่อนอ่านค่าเดิม ·
   AdminLog `settings.store.update` (targetType `StoreSetting`) ในทรานแซกชันเดียวกัน `before`/`after` คีย์เดียวกัน
8. **ส่วนของหน้าที่อ่านข้อมูลร้านอยู่ใน `<Suspense>`** (footer · structured data ใน root layout · หน้าแรก · หน้า CS)
   — โหลดไม่ได้ = ไม่แสดงส่วนนั้น หรือบอกข้อเท็จจริงที่ไม่ต้องใช้ตัวเลข ("ตามเงื่อนไขของร้าน") **ห้ามพิมพ์ค่าสำรองไว้ในซอร์ส**
   (ค่าสำรองคือแหล่งความจริงที่สองที่ค้างค่าเก่า)

| อย่าง                     | เหตุผล                                                                                                                                                   |

## ยังไม่ได้ทำ (บอกไว้ตรง ๆ)

- **อีเมล `hello@teenstyle.ai` เป็นค่าที่โค้ดใช้มาตั้งแต่ STEP 21 — ระบบยืนยันไม่ได้ว่ามีคนเปิดอ่านจริง**
  ร้านควรตรวจที่ `/admin/settings` ก่อนเปิดร้าน (ถ้าไม่มีให้ล้างช่อง = ไม่แสดง)
- **ข้อความในหน้าร้านอัปเดตช้าได้ถึง 60 วินาที** (แคชเหมือนข้อมูลหน้าร้านอื่น · ยังไม่มีใครเรียก `revalidateTag()` — STEP 34)
  ส่วนที่เกี่ยวกับเงินและสิทธิ์ (COD · การคืนสินค้า) ตัดสินที่ backend จากค่าล่าสุดเสมอ
- **เวลาทำการ/วันส่งของเป็นข้อความอิสระ** — ระบบยังไม่รู้ว่า "ตอนนี้มีเจ้าหน้าที่ไหม" (การส่งต่อให้เจ้าหน้าที่นอกเวลายังเข้าคิวได้ตามเดิม)
- **โลโก้ · ยอดสั่งซื้อขั้นต่ำ · กติกาแต้ม** — ดูหัวข้อ "ทำไมบางอย่างไม่ได้อยู่ในหน้านี้"
- **ประวัติของการตั้งค่าดูได้ที่ `/admin/logs`** (หมวด "การตั้งค่าร้าน") แต่ยังย้อนกลับค่าเดิมด้วยปุ่มเดียวไม่ได้
